From taro, on 2026-10-02, before moving the bytecodes to Rust: "wouldn't it
make more sense to solve the 3 points first, and then make the changes to
protocol?". Today the harness has `rom/pruebas/arnes/event_opcodes.py`
generated by `protocol`, and the tests use the numbers for three things:

1. **Building bytecode by hand** and injecting it (`test_posada.py`, …): they
   move to cases written with RM2k commands (`rom/pruebas/casos/`) that the
   real compiler compiles. The ones that deliberately build something the
   compiler would never emit move to the crate's tests or are thrown away.
2. **Checking the bytecode that was compiled** (`test_paginas.py`, …): they
   test the compiler, and go to the tests of `rm2k-snes-events`.
3. **Decoding the music stream** (`musica.py`): it asks
   `rm2k-snes-audio decode` for it.

When this is finished, the next task is declaring the two bytecodes in
Rust and dropping `protocol` and its TOMLs: `bytecodes-declared-in-rust.md`.

comments or docstrings. There are **6 test files and 11 tests**, plus
`arnes/events.py`, which re-exports them:

What there **isn't**, and the assignment assumed:

* **Type 1, bytecode built by hand and injected: none.** `test_posada.py`
  doesn't inject anything: it compares the bum's page, compiled by the real

* **Type 3, decoding the music: already done.** `arnes/musica.py` asks

Comments that name an opcode: about 25 files (`events.py`, `consola.py`,
`musica.py`, `tanda.py`, `animation.py`, `test_curar.py`…). They stay.

## What happens to each one

* **`test_paginas.py`**: the two of the refresh (`la_escritura_despues_de_saltar…`
  and its control) and the three of the cell move to `compile.rs` of
  `rm2k-snes-events`: `a_write_after_jumping_to_another_map_asks_for_the_refresh`,
  `without_jumping_a_write_asks_for_the_refresh_if_the_map_looks`,
  `the_four_of_the_cell_go_in_one_opcode`,
  `the_else_of_the_inner_branch_comes_from_its_destination` and
  `without_the_exact_shape_it_is_not_fused`. They used ABL's maps 6, 49 and
  133 only as context —who looks at 123, which slot each variable has—, and
  in Rust the context is a toy map that looks at 123 or not. The Tram
  Officer one **depends on ABL** (map 9): it stays, checking that the page
  compiles and that its variables have a slot; what it lost is the
  `OP_VAR in codigo`, a loose byte that could be there as an operand of any
  other, and that `ControlVars` compiles to `OP_VAR` is covered by the
  crate's small game (`tests/python.rs`).
* **`test_posada.py`**: it wasn't type 1 but 2. What stays is
  `test_la_pagina_del_bum_compila` (**depends on ABL**: map 20, event 4),
  and the byte by byte moves to
  `an_inn_with_a_price_is_its_greeting_a_choice_and_a_gold_branch`, with the
  same shape: a message and the inn at 5.
* **`test_game_over.py`**: `test_la_derrota_del_jefe_apunta_al_game_over` is
  thrown away. What it checked is already checked by
  `escaping_with_escape_mode_1_ends_the_page` —`escape_mode` and
  `defeat_mode` at 0, which is the shape of the boss's ones, gives
  `[9, 9, BATTLE_LOSE]`—, and that the boss's three compile is still in
  `test_las_tres_paginas_del_jefe_compilan`, which **depends on ABL**.
* **`test_eventos_de_tropa.py`**: `test_el_despegue_pide_su_efecto` read the
  troop's bytecode in the built ROM and looked for `OP_SOUND` with the index
  of `Thunder9`. It moves to `test_el_despegue_toca_su_efecto`, which **hears
  it**: battle, turn 1, and between the orders and the page's message a
  sound effect voice starts with the sample and the frames of the
  `Thunder9` row in `sound_table` —like `test_sonido_en_ruta.py`—. It tests
  more than before: that the index gets to sound, not only that it is
  written.
* **`test_protocolo_contra_el_juego.py`**:
  * `test_el_modulo_de_los_opcodes_esta_al_dia` goes away with the module;
  * the dispatch table one takes the numbers from **the cartridge's
    symbols**: each `OP_X` whose `op_x` exists is an event opcode
    —the music ones have no handler—. It survives the next task,
    because the `.inc` will keep defining it, whoever writes it;
  * the one of the sizes across the whole game moves **inside the
    compiler**: `whole_instructions`, in `compile_page`, walks each page it
    emits by the declared sizes and, if it doesn't land exactly on the end,
    stops the conversion —it is a compiler error, not a page error—. That
    way every `just cartuchos` checks it, with ABL's three thousand-odd. In
    Python what stays is that the whole game goes through there
    (**depends on ABL**), and in Rust
    `a_page_that_does_not_walk_by_the_declared_sizes_stops_the_conversion`.
* **`arnes/events.py`**: without the re-export, without `walk_code` and
  without `CELL_DEST_A/B`, which only the cell ones used.
* **`arnes/event_opcodes.py`** deleted. The recipe that generated it no
  longer existed: since the converter in Rust, whoever changed
  `events.toml` regenerated it by hand, and the test that went away with it
  looked after it.
* **The guard**: `test_ningun_py_de_abl_nombra_un_opcode_en_codigo`, in
  `test_lado_de_abl.py`, with `tokenize`: it fails with an `OP_…`,
  `OPCODE_SIZE`, `opcode_size` or `event_opcodes` in code in `pruebas/`,
  `parches/` or `data/`; not in comments and strings.

## Seen failing

Breaking the compiler or the runtime on purpose, one at a time:

* `Teleport` without `after_jump` → red
  `a_write_after_jumping_to_another_map_asks_for_the_refresh` (and
  `erasing_the_event_after_a_jump_is_nothing`, which already existed);
* `refresh` always asking for it → its control red;
* the two destinations of the cell crossed → red
  `the_else_of_the_inner_branch_comes_from_its_destination` (the one
  without `else` doesn't see it: there the two destinations are the same,
  just like in Python);
* the inn's "Yes" counted from zero (`14` instead of `length + 14`) →
  the inn one red;
* the index of `Thunder9` shifted by one, only for that one → red
  `test_el_despegue_toca_su_efecto` (no voice starts with its sample);
* `.addr op_big_show` and `.addr op_big_move` crossed in
  `event_opcodes.inc` → the dispatch table one red in the three
  cartridges;
* `OP_SWITCH` without the value byte when it switches off → `just cartuchos`
  stops in the conversion: "the compiler emitted a page that does not walk by
  the declared sizes". **Watch out for what this doesn't see**: one byte too
  many or too few that is a zero almost always passes, because `0x00` is
  `OP_DONE` and the walk absorbs it —I tried it first with the inn and it
  passed—. The Python test that went away had the same blind spot.
* The guard: a `.py` with `events.OP_DONE` in code gives red with its line;
  the same name in a comment or in a string doesn't.

only `arnes/event_opcodes.py` was deleted, which is not an installed
script.
